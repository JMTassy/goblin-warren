## What it is (and what it refuses to be)

    session history → behavioral evidence → operator reflection → workflow redesign

NOT:

    logs → AI verdict about identity

The viral mirror prompt is compelling but commits four forbidden morphisms.
The Warren already reasons this way about code; this document extends the
same discipline to reasoning about the operator's *work*.

## The four forbidden morphisms (reject on sight)

    repetition        ⊬ character
    absence           ⊬ avoidance
    timestamp pattern ⊬ psychological motive
    model interpretation ⊬ truth

A live proof of morphism #3, from this repo's own logs: the token "stop"
occurs **13,146×** across 107 session shards. A judging mirror reads
"frustration." The truth: `stopPropagation`, `TaskStop`. The count is real;
the motive is fabricated. **The receipt is not the meaning.**

## The seven epistemic types (every claim wears one)

| Type | Meaning |
|---|---|
| `OBSERVED` | directly counted behavior, dated receipt |
| `RECURRENT` | OBSERVED ≥ 3× (else it is noise, not character) |
| `HYPOTHESIS` | plausible interpretation — never stated as fact |
| `CONTRADICTION` | operator's account conflicts with the record |
| `OPERATOR_MEANING` | interpretation supplied by the person, not the model |
| `ACTION_PROPOSAL` | a reversible workflow experiment |
| `NO_RECEIPT` | unsupported — embargoed from any conclusion |

## The pipeline (each arrow is a gate)

    logs → redacted evidence ledger → hypothesis cards → operator interview → bounded experiment

Not `logs → verdict`. The interview exists because *a conclusion the operator
reaches is load-bearing; the same conclusion handed down, they argue with.*

## The central upgrade: counterfactual autobiography

Do not ask "what pattern defines you?" Ask:

> **Which observed pattern disappears when one workflow constraint changes?**

That single question separates **identity** from **infrastructure**. A
repeated correction may be perfectionism — or unclear prompts, missing
defaults, a weak tool. You cannot tell by counting. You tell by perturbing.

    ┌──────────────────────────────────────────────┐
    │  Do not infer the person until you perturb    │
    │  the environment.                             │
    └──────────────────────────────────────────────┘

Run one reversible intervention. If the repetition vanishes, it was never
character — it was system friction. Metabolize the friction into a tool
(this repo, point 7 below), and the "trait" is gone.

## Why the Warren can host this safely

The mirror is a recursive, self-referential reading — the dangerous kind,
the kind that validates its own claims. The Warren defuses it with the same
separation that governs the game:

    narrator ≠ measurer ≠ operator ≠ reducer ≠ ledger

No single component may generate, validate, authorize, AND canonize the same
claim. The model narrates and proposes; the grep measures; the operator
supplies meaning and verdict; the ledger records. Capability rises; authority
stays external and fixed:

    d(capability)/dt > 0     while     machine_authority = 0

## Recurring friction → new organ (the metabolizing law)

When a friction recurs (RECURRENT), the Warren may grow a non-sovereign
mechanism for it — never a person-verdict:

- repeated semantic promotion → a morphism linter
- repeated unsupported claims → a claim-receipt checker
- repeated ranking drift → deterministic tie-breaking
- repeated dirty-state ambiguity → a decision packet
- repeated deploy failure → a deploy tool with the missing defaults baked in

    recurring failure → new tool
